# vLLM Contribution Playbook

## 1. Config-layer rules (mutation, validation, conditional checks)

- **Validation**: use declarative Pydantic `Field(default=..., ge=..., le=...)`, not hand-rolled `if/raise` blocks (PR #51469, `data_parallel_rpc_port`).
- **Object construction from an existing object**: merge via kwargs, not field-by-field reconstruction. Pattern: `kwargs = {f.name: getattr(spec, f.name) for f in fields(spec) if f.init}; kwargs.update(changes); return target_cls(**kwargs)` — collapsed three ~15-line hand-written constructors into one `replace_as()` helper (PR #51612).
- **Gating an existing operation**: add a `bool` kwarg with a default that preserves old behavior, and fold the extra logic into the shared method — do not add a standalone pre-check helper/method that duplicates the call site. Example: `full_sequence_must_fit: bool = False` added to `allocate_slots`, replacing a separate `KVCacheManager.can_fit_full_sequence` + pre-check-then-call block (PR #41064).
- **Single call site for a check**: model-capability gates live in one place — `ModelConfig.verify_with_parallel_config` (`vllm/config/model.py:1387-1394`), invoked exactly once from `VllmConfig.__post_init__` (`vllm/config/vllm.py:1063`). Don't scatter re-checks elsewhere.
- **Config subtypes go through the same gate as the base, unmodified**: `SpeculativeConfig` builds a full second `ModelConfig` for the draft/MTP head (`vllm/config/speculative.py:897-921`) and calls `self.draft_model_config.verify_with_parallel_config(self.draft_parallel_config)` unconditionally from `_verify_args` (`speculative.py:1382-1385`), with `create_draft_parallel_config` copying `pipeline_parallel_size` verbatim from the target (`speculative.py:1315-1333`). There is no `runner == "draft"` short-circuit anywhere. **Rule**: if a config subtype needs different gate behavior, implement the capability on the object being checked, not a special case in the check.
- **Class/behavior selection driven by an explicit config bool**: `get_scheduler_cls()` (`vllm/config/scheduler.py:170-191`) picks `AsyncScheduler` vs `Scheduler` off `async_scheduling: bool | None`. This is the template for "config decides which implementation runs" — a single factory function, not ad hoc dispatch at call sites.

## 2. Capability/interface rules (where exemptions live)

- **Declare**: `@runtime_checkable Protocol` + `ClassVar[Literal[True]]` flag + required methods/attrs (`interfaces.py`, e.g. `SupportsPP`). A model opts in by subclassing (or duck-typing the same attrs).
- **Check — three legitimate mechanisms, pick by field shape**:
  1. Plain `isinstance(model, SupportsX)` when the Protocol has no `ClassVar[dict/list]` (`SupportsEagle3`, `SupportsEagle`, `SupportsMRoPE`).
  2. Dual "flat" Protocol + explicit dual check when a `ClassVar` holds a dict/list (`runtime_checkable` can't verify `ClassVar` contents via `isinstance`): an attribute/MRO check (`_supports_pp_attributes`) **and** a signature-introspection check (`_supports_pp_inspect` via `supports_kw(forward, "intermediate_tensors")`) — never trust the flag alone (`interfaces.py:718-825`, same pattern for `SupportsLoRA`).
  3. Registry-level, cached, subprocess-safe: `_ModelRegistry.is_pp_supported_model(architectures, model_config) → inspect_model_cls(...).supports_pp` (`registry.py:1408-1414`). **This is what config/scheduler code must call — never `isinstance` a live `nn.Module` directly.** Registry inspection happens on the class, often in a subprocess, before instantiation, to avoid CUDA init.
- **Where a capability gets satisfied without per-model duplication — three real patterns, no others**:
  1. **Wrapper delegation**: outer class declares the capability and forwards plumbing to the inner model it owns, e.g. `self.make_empty_intermediate_tensors = self.language_model.make_empty_intermediate_tensors` in `LlavaForConditionalGeneration`. The registry only ever inspects the outer class.
  2. **Shared generic base class**: implement the protocol once at a base so every subclass gets it for free — `TransformersBase` implements `SupportsPP` generically via `pipeline_parallel()` / `get_pp_indices()` / `PPMissingLayer` (`transformers/base.py`), covering every arbitrary HF architecture with zero per-architecture opt-in.
  3. **Per-class explicit implementation**: the model class declares the flag itself and wires `make_empty_intermediate_tensors` + accepts `intermediate_tensors` in `forward`. `NemotronHMTP` is the only MTP class in the sample that does this; `DeepSeekMTP`, `Glm4MoeMTP`, `Gemma4MTP`, `Qwen3NextMTP`, `LongCatFlashMTP`, `ErnieMTP` do not, and therefore fail `is_pp_supported_model`.
- **Negative rule — no exemption table exists**: `MTPModelTypes` (`speculative.py:37-62`) and `hf_config_override` (`speculative.py:342-392`, rewrites `hf_config.architectures` to the dedicated MTP class) carry zero capability metadata — purely method auto-detection and class-name rewriting. `_SPECULATIVE_DECODING_MODELS` in `registry.py` is just another dict merged into `_VLLM_MODELS`, inspected through the identical `_ModelInfo.supports_pp` path as every other model. **If you want a model role (e.g. a draft/MTP head) exempted from a capability gate, implement the capability on that model class — do not add a role/runner check to the gate itself.**

## 3. Scheduler-change rules

- `Scheduler` (`v1/core/sched/scheduler.py`, ~3000 lines) holds all state and logic. `AsyncScheduler(Scheduler)` (~70 lines) overrides exactly two designated hooks: `_update_after_schedule` and `_update_request_with_output`. It **always calls `super()` first**, then layers its delta.
- **New behavior goes in base `Scheduler.__init__`/`schedule()`/`update_from_output()`, gated by an instance-attribute bool computed once in `__init__`**: `self.use_pp` (`scheduler.py:298`), `self.use_v2_model_runner` (`:299`), `self.use_eagle`, `self.dynamic_sd_lookup`. Cross-cutting flags (PP, spec-decode) are **not** subclass axes — they're checked inline (`if self.use_pp and not self.scheduler_config.async_scheduling:`, `:1495`) because they compose with both sync and async scheduling.
- **Async-only change** → override `_update_after_schedule` or `_update_request_with_output`, call `super()` first. Never write to `AsyncScheduler` state from new base-`Scheduler` logic.
- **Guard clauses over duplicated branches**: wrap a single call/line with `if <mode flag>:` at each affected call site; if a fix touches multiple loops (RUNNING-loop and WAITING-loop), patch both in lockstep with the same shared helper, not parallel logic (PR #51603, Mamba alignment reorder, one-line justifying comment at each site: `"# Apply Mamba alignment before encoder caps."`).
- **Parameters over standalone pre-check methods** — same rule as config layer §1 (PR #41064).
- **Comment discipline**: one-line rationale directly above any reordered/added call; scope-tag legacy paths (`"# MRV1-only:"` on `prev_step_scheduled_req_ids`, `scheduler.py:106`, and on `all_token_ids` in `output.py`); reserve `"# Invariant:"` + an immediate `assert` for genuinely non-local reasoning (only 2 in the file: `scheduler.py:401`, `:2027`); `NOTE(author):` for why-not-what (8 occurrences, e.g. `:478`, `:1293`).
- **Tests named after the invariant, not the code path**: `test_mamba_align_encoder_cache_cap_makes_progress`, `test_cached_request_data_resumed_all_token_ids_mrv1_only`. Exercise both sides of any new mode flag (PR #45840: asserts behavior with `use_v2_model_runner=False` then flips it and re-asserts).
- **Docs-only PRs are a legitimate, separately-landable unit** when they codify a footgun — cite the measured regression/RFC in the body (PR #43724: documents "extend `AsyncScheduler`, not `Scheduler`," citing a measured 78% latency regression and RFC #42185).

## 4. The mergeable-PR checklist (empirical)

1. **Title**: `[Category] specific description` — official categories in `docs/contributing/README.md`: Bugfix, CI/Build, Doc, Model, Frontend, Kernel, Core, Hardware][Vendor, Misc. Not CI-enforced; compound/informal variants merge fine (`[BugFix][Core]` #51482, `[Attention]` #51913) but default to the official set.
2. **Body**: follow `.github/PULL_REQUEST_TEMPLATE.md` — `## Purpose` / `## Test Plan` / `## Test Result`. For bugfixes, **paste the literal traceback/assertion**, don't paraphrase (#51180: `AssertionError: Each KV cache group's real block_size must be divisible by hash_block_size`; #51254: `tvm.error.InternalError: Check failed: num_tokens > 64`).
3. **Tests**: land in the existing subsystem file (`tests/test_config.py`, `tests/v1/...`), parametrized, named after the exact regression (`test_data_parallel_rpc_port_rejects_invalid_ports` #51469, `test_negative_token_ids` #51795, `test_max_num_new_slots_for_drafting` #51256). KV-cache/attention behavior fixes need **both** a unit test and an e2e output-equivalence test toggling the flag (#51756: `test_hybrid_kv_cache_manager_output_equivalence`).
4. **Comments** explain why, citing the PR that introduced the bug when fixing a regression (#52076 citing njhill's own admission in #48017/#51482).
5. **Prefer kwargs-merge/declarative validation** over hand-rolled reconstruction — same rule as §1 (#51612, #51469).
6. **Size**: sampled merged range 2–148 added+deleted lines; many single-digit-to-30-line diffs merge same-day off one MEMBER approval (#51482: 2 lines; #51180: 5 lines; #52076: 19 lines; #52223: 24-line pure deletion).
7. **DCO**: every commit needs `Signed-off-by:` (`git commit -s`) — enforced without exception, merged and closed alike.
8. **AI-assistance disclosure**, if used: explicit disclosure in the PR body + `Co-authored-by:` commit trailer + a human who reviewed every changed line and can defend it end-to-end (`docs/contributing/README.md` § AI Assisted Contributions; #51796, #51756, #51469, #51254).

## 5. Never do (patterns that got called hacky, with why)

- **`isinstance()` a live `nn.Module` for a capability check outside the registry path.** Capability inspection must work on the class, pre-instantiation, sometimes in a subprocess, to avoid CUDA init — use `_ModelRegistry.inspect_model_cls` (`registry.py:1408-1414`).
- **Add a role/runner special-case inside a shared gate** (e.g. `if runner == "draft":` in `verify_with_parallel_config`) to exempt a model type. None exists today; `draft_model_config` runs the identical, unmodified gate (`speculative.py:1382-1385`). Fix belongs on the model class (implement `SupportsPP` there, as `NemotronHMTP` does), not the gate.
- **Subclass `Scheduler` directly** for custom-scheduler work instead of `AsyncScheduler` — documented measured 78% latency regression (PR #43724).
- **Duplicate a check/branch across call sites** when a guard clause or a shared-method kwarg would do — PR #41064 collapsed a standalone pre-check method into a kwarg; PR #51603 required both scheduling loops patched in lockstep with one helper, not parallel logic.
- **Touch `AsyncScheduler`'s state or duplicate its logic from new base-`Scheduler` code.** Extend via the two designated hooks only, always calling `super()` first.
- **Invent a separate "draft capability table" or draft-specific registry.** `_SPECULATIVE_DECODING_MODELS` is just another dict merged into `_VLLM_MODELS`, inspected through the same `_ModelInfo.supports_pp` path as everything else.
- **Unconditional copies in hot scheduler paths** where a mode flag can gate them — PR #45840 replaced an unconditional `all_token_ids` copy with `if not self.use_v2_model_runner:`, tagged `# MRV1-only:` at both definition and use site.
- **Paraphrase a traceback/assertion in a bugfix body** — paste it verbatim (#51180, #51254 convention).
- **Rebase-and-reopen a PR that contradicts a settled maintainer decision.** The same eviction-order PR was resubmitted five times (#51348/#51625/#51631/#51634/#51638), got zero human review each time, and died unmerged — it contradicted the ordering maintainers had just reaffirmed in #51482/#52076.
- **Submit a broad/general-purpose fix when the narrow bug fix suffices.** "Can we just fix the bug instead?" (benjamin chislett, MEMBER) got #52062 CHANGES_REQUESTED and closed in favor of the narrow #52058 fix.
- **Claim a scheduling/perf benefit without a controlled benchmark meeting a predeclared bar.** #51466 was self-withdrawn by its own author after a 25-pair experiment found no workload meeting the bar and regressions up to -6.4% — self-police before a reviewer has to.
- **Skip the DCO signoff or `Co-authored-by:` trailer on AI-assisted commits.** Checked without exception across the sample.
